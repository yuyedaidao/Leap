## Why

Leap 目前需要用户先获取插件文件，再通过本地目录安装。需要让用户粘贴远程插件地址即可安装，同时用一个仓库维护多个插件，并保证只下载所选插件的内容。

## What Changes

- 在设置的插件安装入口增加“从远程地址安装”，保留本地目录安装。
- 首版支持公开 GitHub 仓库中的具体插件目录链接；一个仓库可包含多个自包含插件，每个目录使用现有 `manifest.json`。
- 将分支或标签解析为固定提交，只获取目标插件子树及其中的文件；禁止下载整个仓库归档、完整克隆或在失败后退回全仓下载。
- 提供下载进度、取消和可读错误；下载完成后复用清单校验、信任确认、受管安装及索引刷新。
- 记录插件目录来源与实际提交；替换前明确展示已有插件和来源变化。失败、取消或校验不通过时保留原有插件。
- 补充目录遍历、文件边界、内容信任与安装替换保护，以及相关测试和插件发布说明。

## Capabilities

### New Capabilities

- `remote-plugin-installation`: 单仓库多插件的地址解析、目标目录按需下载、来源确认和安全受管安装。

### Modified Capabilities

无。当前 `openspec/specs/` 尚无已归档能力；本变更沿用已有实现和活动变更中的本地安装约束，以新增能力规格描述远程入口。

## Impact

- 应用界面与状态：`PluginSettingsPage`、`PluginInstallationModel`，必要时独立远程安装表单与下载协调类型。
- 核心：新增 GitHub 地址与目标目录下载能力；复用并补强 `PluginInstaller`、`PluginTrustRecord` 和 `InstalledPluginCatalog` 的内容验证及替换边界。
- 验证：新增远程安装核心测试、安装失败与信任回归测试，调整安装入口相关 UI 测试。
- 文档与发布：更新插件开发指南，约定独立插件仓库的目录组织；用户已指定现有 `yuyedaidao/LeapPlugins` 仓库存放插件，首批为文本转换和数字枚举，不创建新仓库。
- 使用 Foundation 网络能力，不新增运行时依赖。首版不包含私有仓库认证、其他托管平台、插件市场、自动更新或自动安装依赖。
