## Context

动机与产品范围见 [proposal.md](proposal.md)。现有 `PluginInstaller` 支持目录清单检查、内容摘要、信任记录和受管安装；`PluginInstallationModel` 负责确认与列表刷新，`PluginSettingsPage` 提供本地目录选择入口。

当前摘要跳过隐藏文件，安装替换则先删除旧目录再移动暂存目录。接入不受信任的远程文件前，需要保证新下载内容完整参与信任校验，并补上替换失败时恢复旧副本的边界。已有本地安装、内置插件 ID 保护及自包含依赖规则必须继续有效。

## Goals / Non-Goals

**Goals:**
- 用现有清单与安装边界接收远程目录，网络下载和文件准备不阻塞主线程。
- 只传输目标插件文件；读取定位提交和目录所需的元数据，不递归拉取整个仓库的文件树。
- 下载、校验、用户确认和正式安装具有明确边界；未准备完成的目录不参与索引。

**Non-Goals:**
- 不实现通用 Git 客户端、仓库浏览器、共享依赖解析或插件发布服务器。
- 不自动执行插件代码、安装脚本或包管理器；首次运行仍由用户触发。
- 不在本次文档创建中建立 GitHub 仓库或迁移示例文件。

## Decisions

### 1. 仓库按自包含插件目录组织

分发仓库为用户指定的 `https://github.com/yuyedaidao/LeapPlugins`，结构为 `plugins/<plugin-name>/manifest.json` 及同目录脚本、网页、资源和自带依赖，首批为文本转换和数字枚举。下载器不强制仓库名和 `plugins/` 前缀，第三方公开仓库也可使用相同格式。插件目录不得引用兄弟插件或仓库公共目录。

不增加仓库级索引文件：用户已经提供具体插件目录地址，目录树足以确定所需文件。各插件版本由自身清单管理。

### 2. 使用 GitHub 目录链接定位并固定提交

首版接收 `https://github.com/<owner>/<repo>/tree/<ref>/<plugin-path>`；`ref` 支持分支、标签及完整提交标识。拒绝仓库首页、单文件链接、非 HTTPS、含凭据或非 GitHub 的地址，提示提供具体插件目录链接。输入规范化后仍须拒绝空路径、路径越界及编码后的非法路径。

含 `/` 的分支或标签需要基于真实存在的引用解析，采用能匹配的最长引用前缀，剩余部分为非空插件目录；无法唯一定位有效目录时给出错误，不猜测目录。解析产生的网络工作受统一超时和请求边界约束。

下载开始前把引用解析为固定提交。目录枚举和每个文件请求都使用这个提交；下载期间远端分支更新不改变候选内容。

### 3. 只枚举目标子树并逐文件下载

通过 GitHub Git Trees API，沿目标路径取得子树标识，只对目标子树递归读取文件元数据，再从固定提交的原始文件地址下载其中的常规文件。父级树响应可能包含定位所需的兄弟条目，但不请求其他插件的子树或文件正文。

保留目标目录内全部常规文件和相对结构，包括隐藏文件；不根据入口文件推断依赖，以免遗漏动态加载的脚本、图片或自带依赖。拒绝符号链接、子模块和 Git LFS 指针，避免越界访问或把指针当作实际资源。

每次安装创建独立临时目录。采用 Foundation 的异步网络能力和文件落盘下载，最多同时下载 4 个文件。初始上限为 5,000 个文件、单文件 20 MiB、总文件内容 100 MiB、目录深度 32；统一使用具名常量，校验元数据并在实际传输时继续计数。递归列表被截断、响应内容缺失或超限时失败，不安装部分内容。

路径只能写入临时插件根目录；拒绝绝对路径、`..`、重复路径及目标文件系统上的名称冲突。下载只访问 GitHub API 和原始文件的预期 HTTPS 主机，重定向同样检查。网络、状态码和限流错误映射为中文提示，不通过全仓下载绕过失败。

选择该方案是为了保留“直接粘贴源码目录链接”的体验，且不要求每次修改先发布安装包。单插件 Release ZIP 可在以后按需要评估；整仓 ZIP 和完整克隆已被用户明确排除，稀疏检出也不作为首版下载实现。

### 4. 复用受管安装并补强信任边界

完整目录准备后交给 `PluginInstaller.inspect`，复用清单、入口、宿主最低版本与内置 ID 校验。远程安装每次进入明确确认步骤，展示来源目录、实际提交、名称、版本、运行时和命令；已有同 ID 时展示将替换的插件，来源变化需突出说明。来源地址不意味着官方内置信任。

在 `PluginTrustRecord` 增加可选来源信息与可选摘要版本：旧记录缺失字段时仍按旧摘要算法验证，新安装使用覆盖全部常规文件的新版摘要。远程下载只生成常规文件；新安装还需在复制后的暂存目录复核清单与摘要，确保确认内容与实际安装内容一致。不自动将旧记录升级为新信任；本地重新安装时清除旧远程来源，防止来源标注失真。

下载来源信息包含原始目录链接、规范化仓库与目录、实际提交；随信任记录保存，不在插件目录额外写入宿主元数据。`InstalledPluginCatalog` 兼容读取旧记录并可提供来源供后续安装确认使用。

正式替换前准备好暂存副本和新信任记录，保留旧副本与旧信任记录用于失败回滚；任一步骤失败不得留下已删除的旧插件或错误信任的新内容。成功后再移除备份并刷新索引。此保护在共享安装器实现，使本地和远程安装具有一致行为。

### 5. 界面状态和临时资源由安装协调层管理

保留“安装插件”可访问名称及既有标识，将入口扩展为“从本地目录安装”和“从远程地址安装”。远程表单负责地址输入、阶段进度、取消和错误展示；业务放在独立下载类型及 `PluginInstallationModel`，不在 SwiftUI View 执行下载。

界面状态依次为输入、解析、下载、校验、等待确认、安装、完成或失败。下载阶段显示已完成文件数和已下载大小；未取得总量前显示不定进度。准备和确认阶段可取消；正式提交替换阶段短暂禁用取消，保证回滚边界清晰。每次只协调一个候选，防止旧任务回调覆盖新输入。

取消、关闭表单、拒绝信任或准备失败时，取消网络任务并清理临时目录。临时目录在用户确认前保留。现有本地安装入口、更新入口、卸载和内置插件规则保持有效。

记录解析、下载、校验、安装和清理的阶段及失败原因；日志不包含凭据、文件正文或未经处理的敏感查询参数。取消属于正常结束。

## Risks / Trade-offs

- 文件较多时请求次数和延迟增加 → 限制并发、固定提交并展示进度；下载失败明确报告，不回退整仓下载。
- GitHub 的未认证 API 额度和网络可达性影响安装 → 报告限流与网络错误，能取得恢复时间时展示；首版不要求账号或令牌。
- 目录内包含大依赖时触发上限 → 明确显示限制，插件作者保持自包含且控制发布体积；不静默遗漏文件。
- 文件路径和链接由远端控制 → 校验完整文件列表，拒绝特殊条目及名称冲突，实际写入和传输再次检查边界。
- 内容摘要不能证明作者身份，脚本有本机权限 → 展示真实来源并要求明确确认，不授予“内置”身份。
- 新旧摘要算法共存 → 新字段向后兼容，覆盖旧记录及隐藏文件修改的回归测试，不批量重写既有信任记录。

## Migration Plan

1. 先实现可注入网络边界的解析与下载，使用模拟响应证明只请求目标插件内容。
2. 补强共享安装器替换和信任记录兼容性，确保旧插件继续被正确索引。
3. 接入设置入口，覆盖远程取消、确认和既有本地流程，再完成构建、单测、UI 验证与风格检查。
4. 更新插件开发指南，使用 `yuyedaidao/LeapPlugins` 的具体插件目录链接验收。用户于 2026-10-16 明确同意公开仓库，现已通过匿名 API 验证其公开可访问；客户端继续使用无认证下载，不引入私有仓库认证能力。
