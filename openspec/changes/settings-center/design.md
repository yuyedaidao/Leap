## Context

启动器目前由 AppDelegate 创建的 AppKit 浮层承载，齿轮只打开本地插件安装 sheet；全局快捷键固定为 Option-Command-L，系统应用索引和最近记录均已存在于本机。详见 proposal.md。

## Goals / Non-Goals

**Goals:**
- 让所有设置从同一原生窗口管理，并在变更后即时影响启动器。
- 复用现有受管安装、信任校验、使用记录和应用索引，不引入远程服务。

**Non-Goals:**
- 不实现账号、同步、插件市场、遥测、自动更新或应用内语言覆盖。
- 不为未经信任或被篡改的插件提供运行能力。

## Decisions

### 使用原生 Settings 场景

Settings 场景与 SettingsLink 让齿轮和菜单项复用同一窗口，适合四个稳定页面；不继续扩展启动器 sheet，避免其与即时搜索面板耦合。

### 偏好与副作用分离

主题和快捷键数据持久化在 UserDefaults。AppDelegate 持有的设置协调器负责全局快捷键重注册、登录项和启动器刷新，视图只请求操作并显示结果；这避免视图直接管理 Carbon 或 ServiceManagement 生命周期。

### 按前台窗口选择显示器

Carbon 快捷键事件本身不包含显示器信息。回调在激活 Leap 前通过 Quartz 窗口服务读取前台应用最上层可见窗口的边界，并与活动显示器边界计算重叠面积；启动器使用面积最大的显示器。面积相等时依次使用包含窗口中心的候选显示器、鼠标所在的候选显示器。这样既保持常规跨屏窗口的直觉归属，也避免中心落在显示器间隙时退回到无关的鼠标屏幕。随后在主线程将已锁定的显示器 ID 映射为 `NSScreen`。窗口信息不可用时才使用鼠标屏幕，避免用户在副屏工作而鼠标留在主屏时启动器出现在错误位置。几何选择提取为无 AppKit 副作用的类型，以单元测试覆盖多显示器排列。

### 跟随当前桌面空间

启动器不使用 `canJoinAllSpaces`，因为它会让面板出现在所有 Mission Control 桌面空间。面板使用 `moveToActiveSpace`，由 AppKit 在其成为活动窗口时迁移至当前空间，避免唤起 Leap 时跳回首次创建面板的桌面；仍保留 `fullScreenAuxiliary`，以便在全屏应用所在空间显示辅助面板。

### 保持插件信任边界

插件列表只返回与信任记录和内容摘要匹配的受管副本。安装、更新复用既有确认流程；卸载一次性删除对应受管目录和信任记录，随后重新加载启动器以清理失效历史。

### 数据操作即时生效

清除最近记录只删除使用记录。重建应用索引删除磁盘快照后触发既有后台扫描，避免把文件系统扫描放入搜索输入路径。

## Risks / Trade-offs

- [其他应用占用快捷键无法预先枚举] → 仅在系统注册失败时拒绝保存并恢复旧注册。
- [登录项可能需要用户在系统设置批准] → 显示状态与系统入口，不伪造开启成功。
- [卸载不可恢复] → 使用破坏性确认文案并只删除用户明确选定的插件 ID。
- [应用索引重建较慢] → 在后台扫描，并在设置页显示进行状态。

## Migration Plan

新增偏好键在缺失时采用已确认默认值；现有最近记录、插件副本和信任记录不迁移。移除设置功能时可忽略新增偏好键，现有启动器仍使用默认快捷键和系统外观。
