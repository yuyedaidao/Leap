## Context

仓库目前只有 OpenSpec 配置。此设计实现 proposal.md 所述的最小验证闭环，并遵循三份增量规格中定义的可观察行为。

## Goals / Non-Goals

**Goals:**
- 用原生 macOS 宿主验证全局唤起、受管插件、两种脚本运行时和 Web 页面桥接。
- 让安装、信任、运行和故障呈现有单一且可测试的边界。
- 为后续应用启动器、剪贴板和正式 SDK 保留可替换的内部模块边界。

**Non-Goals:**
- 不实现 uTools 兼容、插件市场、自动更新、云同步、应用搜索或剪贴板历史。
- 不发布真实签名、公证产物，也不把证书或凭据放入仓库。
- 不承诺本阶段的插件清单或 JSON-RPC 为公开稳定 API。

## Decisions

### SwiftUI 宿主结合最小 AppKit 集成

使用 SwiftUI 构建搜索面板与错误状态；通过 AppKit/Carbon 注册全局 `Option + Space` 并管理单一浮动面板。选择系统 API 而非第三方快捷键依赖，以减少启动器基础层的分发风险。全局事件监听方案需要额外隐私权限，故不作为首选。

### 受管插件目录和内容信任记录

安装器解析 `manifest.json` 后，计算插件目录内容摘要，并在用户确认后复制到 `Application Support/Leap/Plugins/<id>`。信任记录包含 ID、版本与摘要，任一变化均要求重新确认。直接引用源目录虽便于开发，但外部修改会破坏已确认的内容边界，因此不采用。

### 每个插件使用一个脚本子进程与 JSON-RPC

插件清单的 `runtime` 为 `python` 或 `javascript`，宿主使用 `Process` 启动应用包内对应解释器，通过换行分隔的 JSON-RPC 2.0 在标准输入输出上传递请求和响应。首版按调用启动并设置有限超时；不维护常驻脚本进程，避免进程崩溃与状态泄漏扩大到宿主。

运行时固定放在 App Bundle 的 Resources 中，并在打包阶段同所有嵌套可执行文件一起签名。Python 和 JavaScript 版本由构建配置固定；插件不得触发包管理器下载，依赖随插件目录提供。

### WebView 仅加载受管页面并复用同一调用通道

插件可声明相对 Web 入口。宿主用 `WKWebView` 以受管插件目录为读取边界加载该页面，并注入 `window.leap.invoke`。该桥接通过 `WKScriptMessageHandler` 将页面调用转换为同一 JSON-RPC 请求，响应再返回给页面。直接开放任意原生对象给网页会扩大攻击面，故不采用。

### 最小工程与验证边界

创建 macOS 26 Xcode SwiftUI 应用、Swift Testing 单元测试和 XCUITest 验证。提供一个 Python、一个 JavaScript 和一个带 Web 页面的样例插件。发布脚本只验证签名所需的嵌套可执行文件和公证命令参数；没有证书时必须安全跳过真实提交。

## Risks / Trade-offs

- [捆绑解释器增大体积并增加签名复杂度] → 将运行时拷贝、签名检查和发布验证放入独立构建步骤，先只支持 Apple silicon 开发环境。
- [不受信任脚本可访问用户资源] → 仅运行用户确认且受管副本未变化的插件；首版不承诺沙箱隔离。
- [Web 页面与脚本通信失败] → 使用请求 ID、超时和结构化错误，失败只关闭当前调用。
- [全局快捷键与其他软件冲突] → 启动时报告注册失败；快捷键自定义留给后续设置变更。

## Migration Plan

这是无历史数据的新工程。实现以本地受管目录和可删除的信任记录开始；回滚时删除应用与其 Application Support 数据即可恢复到无宿主状态。
