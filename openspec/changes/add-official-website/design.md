## Context

见 proposal.md。当前仓库为 Tuist macOS 应用，尚无网站；正式图标和插件开发文档可复用。应用版本 1.2.0，目标 macOS 26，运行时准备脚本仅支持 arm64。现有发布脚本不执行真实签名。用户已确认中文、浅色风格、备案后大陆上线及 EdgeOne/COS 路径。

## Goals / Non-Goals

**Goals:** 网站单独构建，应用构建不受影响；预览可在外部资源未就绪时交付；正式构建和发布门禁防止误上线。

**Non-Goals:** 账号、后台、CMS、支付、多语言、插件市场、遥测。

## Decisions

- `Website/` 使用最新稳定 Astro、TypeScript 和原生 CSS。相比 React 应用，静态页面无需浏览器框架运行时；不引入组件库。
- 以温暖浅色、正式图标和真实截图为核心；演示使用本地视频和 poster、用户点击播放，避免自动播放和外部嵌入。
- 构建前读取 `Docs/PluginDevelopment.md` 生成临时 Markdown 导入文件，将相对示例链接映射到同次构建复制的示例资源，避免双份文档漂移。生成文件不入库，使用 Astro 默认 Markdown 处理器，无需新增处理器依赖。
- `release.json` 为下载信息唯一来源；`SITE_URL` 和 `ICP_NUMBER` 属于部署配置。`build:production` 强制检查，普通 build 用于离线预览，不编造域名或备案号。
- 提供失败即停止的发行脚本，校验输入、签名所有嵌套代码、验证并生成 DMG，随后公证和装订。无 Developer ID 或公证配置时不能宣称发行完成。
- 静态产物和下载文件分离；COS 按版本保存不可变地址，手工发布核验后更新元数据，保留旧部署用于回滚。

## Risks / Trade-offs

- [证书、域名与备案缺失] → 先交付本地预览；正式发行、云端部署与大陆验收保持未完成任务。
- [插件能执行外部代码和网络请求] → 如实区分宿主与插件隐私行为，指南强调可信来源。
- [截图暴露个人数据] → 使用隔离数据目录及演示插件拍摄；不使用日常应用数据。
- [运行时签名要求] → 为 JIT 运行时设置必要 entitlement，验证嵌套签名、公证和首次安装；未经实测不标记完成。

## Migration Plan

本地构建与浏览器验收 → 准备签名公证 DMG → 全新机器安装验证 → 配置备案域名和 COS → 上传安装包并核验 SHA256 → 更新 release.json → 正式构建及 EdgeOne 部署 → 大陆网络验收。回滚使用旧网站产物及旧版下载地址，不覆盖已发布安装包。
