## Context

Leap 的搜索模型目前只持有受管插件命令，最近使用也只保存插件 ID 与命令 ID。应用发现必须覆盖标准 macOS 应用位置、保持热更新，并避免文件扫描进入每次按键路径。项目启用了 Swift 6 完整并发检查且已有 200ms 热唤起目标。

## Goals / Non-Goals

**Goals:**
- 在后台建立可缓存、可增量刷新的应用索引，查询只访问内存快照。
- 统一系统应用与插件命令的搜索、激活和最近使用模型。
- 支持中文名称的系统拼音转写及确定性的相关度排序。
- 使用原生系统 API，保持现有权限边界与 Swift 6 并发安全。

**Non-Goals:**
- 不扫描外接磁盘、网络卷或用户任意目录。
- 不提供自定义搜索范围、用户别名、收藏或拼写纠错。
- 不实现面向全盘文件的通用索引器，也不引入 Spotlight、数据库或第三方拼音库。

## Decisions

### 标准目录扫描结合 FSEvents

使用 FileManager 扫描 `/Applications`、`~/Applications`、`/System/Applications` 和 `/System/Library/CoreServices/Applications`，并补充 Finder。递归扫描遇到 `.app` 后立即跳过其后代，避免索引 Helper。符号链接和 Finder Alias 解析到目标后参与去重。

FSEvents 使用文件级事件监听上述目录。事件在串行队列上合并 300ms，再重新扫描受影响的根目录；事件丢失、根变化或要求扫描子目录时重建全部索引。相比逐事件修改索引，根目录重扫能正确处理安装过程的大量合并事件，且应用数量足够小。

### 版本化磁盘快照与不可变内存索引

应用描述只保存稳定文本元数据和 URL，不保存 NSImage。索引快照原子写入 `Application Support/Leap/application-index-v1.json`；冷启动先载入缓存，再后台重建。缓存损坏、版本不兼容或路径失效时忽略并记录日志。

扫描与缓存 I/O 在后台任务执行，主线程只接收新的不可变数组。监听器先启动再执行首次刷新，避免扫描期间遗漏变化。

### 使用 Foundation 生成搜索键

本地化名称先执行大小写、音调和字符宽度归一化，再通过 `applyingTransform(.toLatin)` 与去音调生成拼音，按词生成首字母。每个条目预计算搜索键，查询时进行线性内存评分；几百个应用无需 Trie、SQLite 或倒排索引。

排序采用离散匹配等级：名称完全、名称前缀、单词前缀、拼音完全或前缀、首字母完全或前缀、名称或拼音包含、Bundle ID 包含。文本等级优先；同等级再按最近启动时间、启动次数和本地化名称排序。

### 统一启动器项目与使用记录

引入包含应用和插件命令两种分支的启动器项目类型，视图只根据分支决定副标题、图标与执行动作。最近使用存储升级为带项目键、最后使用时间和累计次数的记录；旧插件命令数组首次读取时迁移，新旧键并存以便回滚。

应用使用 `NSWorkspace.openApplication` 异步启动。成功后记录历史并通知面板隐藏；失败沿用现有调用反馈显示错误。图标仅为可见结果按规范路径缓存在 NSCache 中。

### 键盘选择遵循可见列表方向

搜索框保持焦点时，非空查询的搜索结果使用上下方向键选择，横向最近使用卡片使用左右方向键选择。每个列表默认选中首项，查询或列表变化时重置到首项；方向键在首尾停止、不循环。回车只执行当前可见列表的选中项，避免键盘操作与鼠标点击走出不同的执行路径。

## Risks / Trade-offs

- [FSEvents 会合并或丢弃细粒度事件] → 合并后重扫根目录，检测丢失标志时全量重建。
- [冷启动缓存可能短暂包含已删除应用] → 后台刷新尽快替换快照，执行前再次确认 URL 可达，失败时不写历史。
- [系统拼音转写对多音字不完全准确] → 首版接受系统转写，保留本地化名称与 Bundle ID 搜索作为稳定路径。
- [重复 Bundle ID 可能来自多个安装副本] → 优先保留用户目录、全局目录、系统目录顺序中的第一个规范路径，并记录去重决定。

## Migration Plan

新增索引缓存可随时删除并重建。最近使用首次加载时把旧 `RecentCommandKey` 按原顺序转换成统一记录，同时保留旧 UserDefaults 键；回滚代码仍可读取旧数据。部署不修改插件目录、信任记录或运行时资源。
